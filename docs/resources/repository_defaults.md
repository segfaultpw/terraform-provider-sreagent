# sreagent_repository_defaults (Resource)

The organization's repository defaults: the six settings (fix_runner, platform_fallback, auto_dispatch, draft_prs, check_network, allow_ci_config) every repository follows until it holds a value of its own (sreagent_repo_setting).

The platform applies a change only against a preview of what it moves, so terraform plan asks for that preview (it needs an api:admin key; with an api:config_read key the plan says so and the apply previews and applies) and warns with the settings that change, the repositories that read a different value and the child organizations that follow these defaults. The apply sends the plan's fingerprint, and fails without writing when what would move changed since. Turning allow_ci_config or check_network on needs the matching entry in confirm.

One row per organization: creating the resource adopts the current defaults, a setting the configuration leaves out is left as it is, and draft_prs cannot be put back to the installation's setting from Terraform (do it in the app). An organization with a parent that follows the parent's defaults has no row of its own: creating the resource gives it its own for all six settings and stops it following the parent, and destroying the resource follows the parent again. In an organization with no parent, destroying the resource leaves the defaults in place.

## Example Usage

```terraform
# What every repository follows until it holds a value of its own. A change is
# previewed by the platform at plan time (the plan lists the repositories that
# move) and applied against that preview.
resource "sreagent_repository_defaults" "this" {
  auto_dispatch     = false
  platform_fallback = true

  # Turning allow_ci_config or check_network on needs the matching entry here.
  allow_ci_config = true
  confirm         = ["ci_config"]
}
```

## Schema

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `allow_ci_config` (Boolean) Whether fixes may change CI configuration inside the write fence of following repositories. Turning it on needs confirm to name ci_config. With this on, a fix may change CI configuration, and the repository's CI runs that change as soon as the branch is pushed, with the repository's secrets, before anyone reviews the pull request.
- `auto_dispatch` (Boolean) true sends a following repository's fix requests as soon as they are made. false holds each until a person presses Send.
- `check_network` (Boolean) Whether the commands after setup (checks, tests, analysis) of following repositories may reach GitHub and the package registries while a fix is checked. Turning it on needs confirm to name check_network and is accepted only where the Integrations page offers it.
- `confirm` (List of String, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The confirmations a change needs: ci_config when it turns allow_ci_config on, check_network when it turns check_network on. The plan fails without the one the preview asks for. Naming a confirmation never writes anything by itself. One of: ci_config, check_network. Write-only: never stored in state or plan.
- `draft_prs` (Boolean) Whether a following repository's fix pull request opens as a draft (true) or ready for review (false). Null means the GitHub installation's setting decides; once set, Terraform cannot return it to null, do that in the app.
- `fix_runner` (String) Who executes the fix requests of repositories that follow: platform (SRE Agent's own agent) or self_hosted (a runner on your own machine, which needs one registered for the organization; included in the Business and Enterprise plans).
- `platform_fallback` (Boolean) true lets a request a following repository's own runner could not finish run on SRE Agent's own runner. false keeps the code on your machines: the request fails with a plain sentence instead.

### Read-Only

- `id` (String) The row's identifier on the platform.
- `parent_name` (String) The parent organization's name, or null for an organization with none.
- `preview_fingerprint` (String) The fingerprint of the preview the plan took, which the apply sends. Kept by the provider; never configure it.
- `source` (String) Where the values come from: own (this organization set them), parent (a child organization follows its parent's) or built_in (none set).
- `stopped` (Boolean) True when a child organization chose to stop following its parent.
- `updated_at` (String) When the organization's own defaults last changed, or null.
