# sreagent_repository_defaults (Data Source)

The organization's repository defaults: the seven settings (fix_runner, platform_fallback, auto_dispatch, draft_prs, check_network, allow_ci_config, auto_merge) every repository follows until it holds a value of its own (sreagent_repo_setting).

The platform applies a change only against a preview of what it moves, so terraform plan asks for that preview (it needs an api:admin key; with an api:config_read key the plan says so and the apply previews and applies) and warns with the settings that change, the repositories that read a different value and the child organizations that follow these defaults. The apply sends the plan's fingerprint, and fails without writing when what would move changed since. Turning allow_ci_config, check_network or auto_merge on needs the matching entry in confirm.

One row per organization: creating the resource adopts the current defaults, a setting the configuration leaves out is left as it is, and draft_prs cannot be put back to the installation's setting from Terraform (do it in the app). An organization with a parent that follows the parent's defaults has no row of its own: creating the resource gives it its own for all seven settings and stops it following the parent. Destroying the resource hands it back to the parent, and that is planned like any other change: the destroy plan asks the platform what it moves and warns with the settings that change and the repositories that read a different value (it also ends a stop the organization made in the app, even when no value moves). When the parent's defaults turn allow_ci_config, check_network or auto_merge on, the platform wants a confirmation, which a destroy cannot carry: set confirm_on_destroy, apply, then destroy, or the destroy plan fails and says so. In an organization with no parent, destroying the resource leaves the defaults in place and moves nothing, and the plan says so.

## Example Usage

```terraform
# configured is false for a child organization that follows its parent's defaults.
data "sreagent_repository_defaults" "this" {}

output "fix_runner" {
  value = data.sreagent_repository_defaults.this.fix_runner
}
```

## Schema

### Read-Only

- `allow_ci_config` (Boolean) Whether fixes may change CI configuration inside the write fence of following repositories. Turning it on needs confirm to name ci_config. With this on, a fix may change CI configuration, and the repository's CI runs that change as soon as the branch is pushed, with the repository's secrets, before anyone reviews the pull request.
- `auto_dispatch` (Boolean) true sends a following repository's fix requests as soon as they are made. false holds each until a person presses Send.
- `auto_merge` (Boolean) Whether the fix pull requests of following repositories merge by themselves once the checks their branch requires pass. Off unless set. Turning it on needs confirm to name auto_merge. SRE Agent asks GitHub to merge a fix pull request by itself when the checks its base branch requires are still running, and merges it itself when they have already passed, and only where the repository allows auto-merge and the base branch requires at least one status check. A draft, a change SRE Agent's own checks ran on and could not judge, a change to CI files, IAM or Kubernetes manifests, and a self-healing pull request whose area is below full autonomy never merge this way. Your organization's admins take the risk of a merge nobody reviewed. By default it merges what the branch's required checks let through, whether SRE Agent's own checks ran or not; auto_merge_requires_verification on sreagent_github_settings ("Auto-merge only what SRE Agent verified") limits it to what those checks passed. To stop one pull request: comment /hold on it, request changes in a review, convert it to a draft, or turn auto-merge off on GitHub. A configuration that states auto_merge = true without confirm fails the plan again whenever the platform stops reading it on (a person turned it off in the app, or a default the organization followed was turned off): add confirm = ["auto_merge"] for the apply that turns it on again, or set auto_merge to false (or remove the line) to leave it off.
- `check_network` (Boolean) Whether the commands after setup (checks, tests, analysis) of following repositories may reach GitHub and the package registries while a fix is checked. Turning it on needs confirm to name check_network and is accepted only where the Integrations page offers it.
- `configured` (Boolean) False when the organization has no row of its own yet (or reads its parent's); every other attribute is then null.
- `draft_prs` (Boolean) Whether a following repository's fix pull request opens as a draft (true) or ready for review (false). Null means the GitHub installation's setting decides; once set, Terraform cannot return it to null, do that in the app.
- `fix_runner` (String) Who executes the fix requests of repositories that follow: platform (SRE Agent's own agent) or self_hosted (a runner on your own machine, which needs one registered for the organization; included in the Business and Enterprise plans).
- `id` (String) The row's identifier on the platform.
- `parent_name` (String) The parent organization's name, or null for an organization with none.
- `platform_fallback` (Boolean) true lets a request a following repository's own runner could not finish run on SRE Agent's own runner. false keeps the code on your machines: the request fails with a plain sentence instead.
- `source` (String) Where the values come from: own (this organization set them), parent (a child organization follows its parent's) or built_in (none set).
- `stopped` (Boolean) True when a child organization chose to stop following its parent.
- `updated_at` (String) When the organization's own defaults last changed, or null.
